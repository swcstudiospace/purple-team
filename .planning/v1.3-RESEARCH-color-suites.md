# v1.3 Research: Black / Blue / White Suites at Red Parity

**Gathered:** 2026-10-10 · **Status:** For owner scope decision
**Method:** Two read-only inventories of the current tree — (A) the color-team
modules (`src/teams/*`) and (B) the red-suite depth baseline
(`src/arsenal/catalog.ts`, `src/resources/ai-redteam-playbook.ts`,
`src/mcp-server.ts`, bench harnesses). All numbers below are measured, not
estimated.

## 1. The bar: what "red parity" means

| Surface | Red (measured today) |
|---|---|
| Tool catalog | 21 categories, 62 adapters (`ToolAdapter`: id, binary, category, families, risk, execution, evidenceKinds, parserStatus) |
| Playbook | 21 techniques (`RedTeamTechnique`: id, category, principle, redteamUse, defense) with briefing pipeline into operator context |
| Bench harness | 2 corpus+judge harnesses (`cve-hunt-bench`: 5 hunter modes, SPHINX judge, 5 gates, decoy penalties, 17-sample manifest; `cloud-misconfig-bench`: checkov vs IaC corpus, detection + discrimination axes) |
| Payload/knowledge DBs | 200+ payloads, 15+ secret patterns, 50+ privesc techniques |
| MCP proxy | 5 `tempest_*` loopback tools (bearer-gated off loopback since v1.2) |
| Execution depth | LLM-backed missions, receipts, evidence ledger, persistence |

## 2. The gap: what black/blue/white have today

Inventoried state of `src/teams/{index,hats,blue,white,purple}.ts`:

- **Grants:** `teamToolGrants()` slices the *red* catalog — the colors own zero
  adapters. Invariants: grants reference existing catalog ids; black stays
  disjoint from blue/white.
- **Pipelines are pure heuristics over plain data, no I/O, no LLM, no persistence:**
  - `blue.detectionGaps()` — coverage is a string match of finding ids against
    telemetry `coveredIds`; recommendations come from a severity→control text table.
  - `blue.hardeningPlan()` — groups findings by severity tier.
  - `white.roeAudit()` — regex precedence (out-of-scope target → active technique → approval receipt).
  - `white.adjudicateEvidence()` — infers strength from entry `type` (receipt/screenshot→replayable, command→tool, artifact→context).
  - `purple.synthesize()` — matches `RoeVerdict` to findings **positionally**
    (verdict *i* ↔ finding *i*, extras ignored). Weakest link in the loop.
- **Hats (6):** specter/wraith (black), sentinel/warden (blue), arbiter/auditor
  (white) — doctrine + grant slices + pure functions
  (`specterCoverReview`, `wraithExfilSim`, `sentinelDetectorMap`,
  `wardenHardeningReview`, `arbiterDispute`, `auditorScore`).
- **Routes:** `/api/teams/tool-grants`, `/api/teams/purple/synthesize`. Grokbot:
  7 hat skills are text-only grammars over generic endpoints; no color-specific
  MCP tools, benches, playbooks, or UI surface.

**Conclusion:** the colors are doctrine, not suites. Parity requires four
things per color: own adapters, a techniques playbook, a corpus+judge bench,
and real routes/skills — plus the purple correlation fix.

## 3. Proposed modules

### 3.1 Blue — defensive engineering

- **Catalog:** new category `detection`. Adapter candidates (honest
  `parserStatus`, `execution` modes per the existing interface):
  `sigma` (sigma-cli — rule authoring/translation, `receipt_required`),
  `atomic-red-team` (ATT&CK technique catalog as data, `import_only`),
  `osquery` (query pack validation, `catalog_only` initially),
  `velociraptor` (IR collection grammar, `catalog_only`),
  `suricata` (rule syntax validation, `catalog_only`).
  Posture: analysis/validation only — no live EDR/SIEM operation.
- **Modules:** `src/teams/blue/` — telemetry source registry with real
  `coveredIds` semantics; rule-pack generator emitting Sigma YAML per
  `DetectionGap`; coverage scorer keyed by technique/mitigation id (D3FEND),
  replacing the severity→text table.
- **Playbook:** `ai-defense-playbook.ts` mirroring `RedTeamTechnique`:
  `{ id, category, telemetry, signal, validation }` (~15–20 techniques).
- **Bench:** `scripts/detection-coverage-bench.mjs` + `bench/detection-coverage/`
  corpus (labeled finding/telemetry pairs with ground-truth gaps; decoys).
  Hunter = blue v2; judge/gates mirror `cloud-misconfig-bench`.
- **Routes/skills:** `GET/POST /api/teams/blue/{gaps,hardening,rules}`;
  wire `blue-sentinel`/`blue-warden` skills to real backends; MCP
  `tempest_blue_gaps`.

### 3.2 Black — adversary emulation & opsec

- **Catalog:** new category `emulation`: `attack-navigator` (layer data,
  `import_only`), `caldera` (emulation plan *parsing*, `catalog_only`),
  shares `atomic-red-team`. Everything else stays pure modules — black is
  analysis of tradecraft, never execution.
- **Modules:** `src/teams/black/` — `specterCoverReview` v2 with a structured
  noise budget (per-action detection-surface score, not prose);
  `wraithExfilSim` v2 with an egress path cost model; OPSEC checklist engine
  keyed to mission phases.
- **Playbook:** `{ id, attckId, opsecRisk, detectionSurface, tradecraftUse }`
  (~15–20 techniques).
- **Bench:** `scripts/opsec-review-bench.mjs` — corpus of red plans with
  ground-truth opsec flags; hunter = specter v2; decoy plans included.
- **Routes/skills:** `/api/teams/black/{cover,exfil,noise}`; wire
  `black-specter`/`black-wraith`; MCP `tempest_black_cover`.

### 3.3 White — governance & evidence

- **Catalog:** `governance` data packs, all `import_only`/`catalog_only`:
  NIST SP 800-115, PTES, OSSTMM sections as structured catalogs (no binaries).
- **Modules:** `src/teams/white/` — ROE parser (structured `RoeSpec` from
  operator text), evidence-chain validator (provenance + replay hooks into the
  existing receipt ledger), report auditor (findings↔evidence coverage check).
- **Playbook:** `{ id, framework, control, adjudicationRule, evidenceStandard }`.
- **Bench:** `scripts/roe-adjudication-bench.mjs` — action/ROE pairs with
  ground-truth verdicts; evidence-strength fixtures.
- **Routes/skills:** `/api/teams/white/{roe,evidence,report-audit}`; wire
  `white-arbiter`/`white-auditor`; MCP `tempest_white_roe`.

### 3.4 Purple v2 (prerequisite-grade fix)

- Correlate by **finding id**, not array position; residual risk =
  f(severity, detection coverage, ROE verdict); feed bench results back as
  detections. Persist color artifacts alongside the existing ledgers.

## 6. Risks & open decisions

1. **Corpus authoring is the biggest lift** — three benches need ground-truth
   corpora. Reuse the decoy/judge discipline from `cve-hunt`; budget a phase each.
2. **Execution posture** — proposal keeps blue/black/white analysis-only
   (`receipt_required` at most, no live estate operation). Owner should confirm.
3. **Adapter ids must exist before grants reference them** — existing
   invariant; catalog and grants land in the same phase per color.
4. **`tauri.localhost`/bearer interplay** — color routes are `/api/*`, so the
   v1.2 guard covers them with no new work.
