# Plan 12-01: Node server sidecar (bundle, wire, spawn, docs)

## Steps

1. **Sidecar build script** — `scripts/build-sidecar.mjs` (new) + `package.json`
   script `sidecar:build`. Chain: existing `tsc` output (`dist/server.js`) →
   `@yao-pkg/pkg` compile → `src-tauri/binaries/t3mp3st-server-<triple>` where
   `<triple>` derives from `process.platform`/`process.arch`
   (linux-x64 | win-x64 | darwin-x64 | darwin-arm64). Add `@yao-pkg/pkg` as
   devDependency.
   - Verify: `npm run sidecar:build` produces an executable binary; running it
     standalone with `T3MP3ST_PORT=3399` serves the loopback API.
2. **Conf wiring** — `src-tauri/tauri.conf.json`: `bundle.externalBin:
   ["binaries/t3mp3st-server"]`, plus `bundle.resources: ["../docs"]` (sidecar
   serves /ui from disk relative to its cwd).
3. **Rust lifecycle** — `src-tauri/src/lib.rs`: spawn on setup when
   `!tauri::is_dev()` (exe-dir `t3mp3st-server`, env `T3MP3ST_PORT=3333`,
   cwd = exe dir), readiness = retry `TcpStream::connect("127.0.0.1:3333")`
   (bounded ~10s, no new crates), kill+wait on `RunEvent::Exit`, spawn failure
   logs and continues (degraded shell, no crash). No `tauri-plugin-shell` —
   capabilities lockdown unchanged.
4. **Ignore + CI** — `.gitignore` += `src-tauri/binaries/`;
   `.github/workflows/tauri-build.yml` gains `npm run sidecar:build` after
   `npm run build` (externalBin must exist before `tauri build`).
5. **Docs** — `docs/TAURI.md`: §2 prod sequence becomes sidecar-driven;
   §3 follow-up 2 (node sidecar) closed with the decision record
   (tsc-dist + @yao-pkg/pkg; why not Node SEA/nexe).
6. **Gates + artifacts** — SUMMARY.md; ROADMAP/STATE flip; commit; push.
